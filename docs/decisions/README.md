# 設計判断記録（ADR）

screen-spec の確定した設計判断を記録する正式なディレクトリ。

## 二層運用（[CLAUDE.md](../../CLAUDE.md) 参照）

- **`.knowledge/`（Obsidian・commit 禁止）**: 検討途中のメモ・スクラッチ。
- **`docs/decisions/`（このディレクトリ・リポジトリの正式記録）**: 確定した設計判断。
- `.knowledge` から昇格する際は内容を確認のうえ、ここへ転記する。

## v0.1 決定の一覧

| # | 論点 | 決定 |
|---|---|---|
| 1 | 記述形式 | YAML 主体 + JSON Schema (draft 2020-12) 検証 |
| 2 | コンポーネント再利用 | `components` + `$ref`（v0.1 から必須） |
| 3 | `$ref` セマンティクス | 純粋参照（兄弟キー禁止・マージなし、OpenAPI 3.0 互換） |
| 4 | バリエーション | 上書きではなく別コンポーネントとして定義 |
| 5 | コレクション構造 | 全面マップ化（キー＝識別子、`id` プロパティ廃止） |
| 6 | 表示順 | YAML 記述順を正とする |
| 7 | 参照解決 | `core` にリゾルバ、2 段検証（raw → resolve → resolved） |
| 8 | 外部参照 | ローカル相対パスのみ |
| 9 | キー命名規則 | 用途別 3 規則（定義=Pascal / 実体=camel / 画面ID=kebab） |
| 10 | 状態遷移の厳密さ | 案C（中間）。`from`/`to` 必須、網羅性は警告 |
| 11 | OpenAPI 連携の深さ | 案B（参照＋項目マッピングのみ） |
| 12 | `compose`（allOf 相当） | 予約のみ・v0.1 非スコープ |
