# Permission

ロールベースのアクセス設計情報。新規仕様では `screen.accessControl.roles` に集約します。

:::note
v0.1 の権限は **設計情報としての記述**です。実行時の認可制御は行いません。
:::

## 権限マトリクス

| resource | operation | 説明 |
|---|---|---|
| `screen` | `view` | 画面を閲覧できるか |
| `fields.<key>` | `view`, `edit` | 項目を閲覧・編集できるか |
| `events.<key>` | `execute` | eventを実行できるか |

未指定はdenyです。`"*"` はfield/eventの既定値で、個別指定がoperation単位で上書きします。

## 例

```yaml
screen:
  id: user-edit
  name: ユーザー編集画面
  accessControl:
    roles:
      admin:
        screen: { view: true }
        fields:
          "*": { view: true, edit: true }
        events:
          "*": { execute: true }
      editor:
        screen: { view: true }
        fields:
          "*": { view: true, edit: false }
          name: { edit: true }
          email: { edit: true }
        events:
          submit: { execute: true }
```

`edit: true` には継承後の `view: true` が必要です。未定義のfield/event参照と矛盾はwarningになります。

## 旧形式

`screen.permissions` と `field.permission` は後方互換のため引き続き有効ですが非推奨です。
`accessControl`との併用はwarningになるため、新規記述では使わないでください。
