# Event

状態間の遷移。`screen.events` マップの値として定義します（キーがイベント識別子・camelCase）。

## フィールド

| キー | 型 | 必須 | 説明 |
|---|---|---|---|
| `from` | string | ✔ | 遷移元の状態キー |
| `to` | string | ✔ | 遷移先の状態キー（即時遷移先） |
| `expects` | object | | 即時遷移の期待結果 |
| `trigger` | string | | 契機。例 `click`, `screenLoad` |
| `target` | string | | 対象 UI 要素 |
| `action` | object | | `{ apiCall: <apiBinding キー> }`（v0.1 では未検証） |
| `onSuccess` | object | | `{ to, navigate, expects }` |
| `onError` | object | | `{ to, expects, cases }` |

`from` / `to` / `onSuccess.to` / `onError.to` は `states` に存在するキーである必要があります
（未定義ならエラー）。

## 例

```yaml
events:
  submit:
    trigger: click
    target: submitButton
    from: editing
    to: submitting
    action: { apiCall: updateUser }
    onSuccess: { to: viewing, navigate: user-list }
    onError: { to: error }
```

`action` を伴う場合、`to`（例: `submitting`）を起点に `onSuccess.to` / `onError.to` へ分岐します。
`apiCall` は [ApiBinding](/concepts/state-machine)への参照です。

## 期待結果とAPIエラー

`expects` は `state`、`navigate`、`message`、フィールドごとの `value` / `expression` / `visible` /
`enabled` を表現します。`onError.cases` はHTTP `status` と業務エラー `code` で分岐し、
一致しない場合は `onError` 直下を既定結果として使います。

```yaml
onError:
  to: error
  cases:
    - when: { status: 409 }
      to: conflict
      expects:
        state: conflict
        message: { kind: warning, text: 他のユーザーにより更新されています }
  expects:
    state: error
    message: { kind: error, key: update.failed }
```
