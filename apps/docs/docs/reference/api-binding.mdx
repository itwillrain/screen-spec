# ApiBinding

`screen.apiBindings` マップの値（キーが連携識別子・camelCase）。

## フィールド

| キー | 型 | 必須 | 説明 |
|---|---|---|---|
| `openapi` | object | ✔ | `{ operationId, specRef }` |
| `request` | object | | `{ path, query, body }`（各 ExpressionMap） |
| `response` | object | | `{ mapping }`（ResponseMapping） |
| `description` | string | | 補足説明 |

### openapi

| キー | 型 | 必須 | 説明 |
|---|---|---|---|
| `operationId` | string | ✔ | OpenAPI の operationId |
| `specRef` | string | ✔ | OpenAPI定義への参照（ローカル相対パス） |

### ExpressionMap / ResponseMapping

`request.path/query/body` のExpressionMapは「API フィールド → 式」、
`response.mapping` のResponseMappingは「`fields.<fieldId>` または `data.<dataId>` → APIレスポンスのパス」。裸のField IDは互換形式です。

- request: `{screen.route.userId}` / `{fields.name}`（テンプレート式として構文と参照を検証）
- response: `data.name`（OpenAPIの2xx JSONレスポンスに存在するproperty pathか検証）

## 例

```yaml
apiBindings:
  getUser:
    openapi:
      operationId: getUserById
      specRef: ../../openapi/users.yaml
    request:
      path: { userId: "{screen.route.userId}" }
    response:
      mapping:
        fields.name: data.name
        fields.email: data.email
```

詳しくは [API 連携](/concepts/api-bindings) を参照。
