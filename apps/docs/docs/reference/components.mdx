# Components

Componentは、`components`配下に名前付きで登録された、取得元に依存しない再利用可能な完全な仕様契約です。実際の参照回数ではなく、登録された再利用意図によってComponentとなります。
OpenAPI の `components` に相当します。定義名は **PascalCase**（[命名規則](/concepts/naming)）。

同じ意味とUI契約を持つComponentは取得元が異なっても再利用できます。意味または確定仕様が異なる場合は、見た目が同じでも別Componentとして定義します。継承・差分合成は行いません。

Component Identityは解決後の文書URIとJSON Pointerの組です。同名でも定義先が異なれば別Componentです。正式な種別はField Component、Validation Component、Options Componentです。独自契約を持たず別Componentを単独`$ref`するComponent Aliasは禁止します。

## サブセクション（v0.1）

| セクション | 定義する部品 |
|---|---|
| `components.validations` | [Validation](/reference/validation) |
| `components.fields` | [Field](/reference/field) |
| `components.options` | [Options](/reference/options) |

## 例

```yaml
specVersion: "0.1"
components:
  validations:
    Required:
      rule: required
      message: 必須項目です
    EmailFormat:
      rule: pattern
      value: "^[^@\\s]+@[^@\\s]+\\.[^@\\s]+$"
      message: メールアドレスの形式が正しくありません
  fields:
    EmailField:
      label: メールアドレス
      type: email
      required: true
      validations:
        - $ref: "#/components/validations/Required"
        - $ref: "#/components/validations/EmailFormat"
  options:
    RoleOptions:
      - { value: admin, label: 管理者 }
      - { value: editor, label: 編集者 }
      - { value: viewer, label: 閲覧者 }
```

Componentの契約内から別種のComponentを`$ref`できます（上の`EmailField`から`Required`へのComponent Dependency）。Component定義全体を別Componentへの`$ref`だけにするAliasはできません。参照は純粋参照で、兄弟キーは書けません（[`$ref`ガイド](/concepts/refs)）。利用関係と変更影響の規則は[Component Usage](/concepts/component-usage)を参照してください。
