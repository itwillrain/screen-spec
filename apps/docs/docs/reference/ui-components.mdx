# UI Components

UI Componentは、Pagination、DataTable、Header、Sidebar、Footerのように複数の表示要素と操作を一体として扱う、取得元と実装に依存しないComponentです。内部Fieldは公開せず、外部Contractだけを定義します。

## Component Contract

`components.ui`へPascalCaseで登録します。

```yaml
components:
  ui:
    Pagination:
      name: ページネーション
      inputs:
        currentPage: { type: integer, required: true }
        pageSize: { type: integer, required: true }
        totalCount: { type: integer, required: true }
        loading: { type: boolean, default: false }
      events:
        pageChange:
          required: true
          payload:
            page: { type: integer, required: true }
      parts:
        previous: { kind: action }
        next: { kind: action }
        pageNumbers: { kind: collection }
      derived:
        totalPages:
          type: integer
          expression: ceil(inputs.totalCount / inputs.pageSize)
      rules:
        - when: inputs.currentPage == 1
          target: parts.previous
          enabled: false
      accessibility:
        landmark: navigation
        label: ページネーション
      responsive:
        compact:
          preserves: [previous, next]
          omits: [pageNumbers]
```

Inputsは値の型、必須性、任意のdefaultを定義します。EventsはComponentが通知する契機とPayloadです。PartsはFieldではなく、Rules・Accessibility・Responsiveから参照するsemantic partです。Derivedは宣言済みInputだけから求める副作用のない値です。

## Component Instance

Screenでは`ui`へInstanceを定義し、InputとEventを画面固有の契約へ明示的に接続します。

```yaml
screen:
  ui:
    userPagination:
      component:
        $ref: "./common.yaml#/components/ui/Pagination"
      bindings:
        currentPage: { source: data.userPage }
        pageSize: { source: data.userPageSize }
        totalCount: { source: data.userTotal }
        loading: { source: api.listUsers.loading }
        pageSizeOptions: { value: [20, 50, 100] }
      events:
        pageChange: changePage
```

Bindingは`source`または固定`value`の一方です。必須Inputと必須Eventは接続が必要です。Component EventのPayloadは接続先Screen Eventで`event.payload`として参照できます。

## Screen Outline

`layout.sections[].items`へFieldとComponent Instanceを定義順に配置します。Sectionは平坦で、`region`に`header`、`sidebar`、`body`、`footer`を指定します。入れ子Regionは扱いません。

```yaml
layout:
  sections:
    - { id: header, region: header, items: [{ component: appHeader }] }
    - id: results
      region: body
      items:
        - field: keyword
        - component: userTable
        - component: userPagination
    - { id: footer, region: footer, items: [{ component: appFooter }] }
```

同じInstanceを複数配置せず、配置ごとに別Instance IDを定義します。既存の`sections[].fields`はv0.1の互換形式として受理します。
