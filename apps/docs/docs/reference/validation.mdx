# Validation

フィールドの検証ルール。`field.validations` の要素、または `components.validations` の定義として使います。

## フィールド

| キー | 型 | 必須 | 説明 |
|---|---|---|---|
| `rule` | string | ✔ | ルール名。例 `required`, `maxLength`, `pattern` |
| `value` | any | | ルールのパラメータ（`maxLength` の桁数、`pattern` の正規表現など） |
| `message` | string | | 検証失敗時に利用者へ提示するメッセージ。省略するとCompleteness Diagnosticのwarning |

## 例

```yaml
components:
  validations:
    Required:
      rule: required
      message: 必須項目です
    EmailFormat:
      rule: pattern
      value: "^[^@\\s]+@[^@\\s]+\\.[^@\\s]+$"
      message: メールアドレスの形式が正しくありません
```

`message`はスキーマ上省略可能ですが、画面仕様として検証失敗時の表示を判断できなくなるため、Analyzerは`validation-message-missing` warningを報告します。

インラインでも記述できます。

```yaml
validations:
  - rule: maxLength
    value: 50
    message: 50文字以内で入力してください
```

## ルール語彙（形式化）

テスト項目（境界値・同値分割）の自動導出と実装の意味論のため、既知ルールを語彙として定義しています
（[ADR 0002](https://github.com/itwillrain/screen-spec/blob/main/docs/decisions/0002-spec-coverage-retrospective.md)）。
既知ルールは `value` の型がスキーマで強制されます。**未知のルールも書けますが**、検証で **warning**
となり（テスト自動導出の対象外）ます。

| rule | value | 対象 | 意味 |
|---|---|---|---|
| `required` | なし | any | 必須（空でない） |
| `minLength` / `maxLength` | integer | string | 文字数 |
| `pattern` | string | string | 正規表現に一致 |
| `email` / `url` | なし | string | 形式 |
| `enum` | array | any | 許可値のいずれか |
| `min` / `max` / `step` | number | number | 数値制約 |
| `minDate` / `maxDate` | string | date | 日付制約 |

```yaml
validations:
  - rule: required
    message: 入力してください
  - rule: maxLength
    value: 50
    message: 50文字以内で入力してください
  - rule: min
    value: 0
    message: 0以上で入力してください
```
