# Examples

リポジトリの`examples/`には、画面、共通Component、OpenAPI、testDataのサンプルがあります。

## ディレクトリ構成

```text
examples/
├─ components/
│  ├─ validations.yaml
│  ├─ fields.yaml
│  ├─ options.yaml
│  └─ ui.yaml
├─ pages/
│  ├─ users/
│  │  ├─ list.screen.yaml
│  │  └─ edit.screen.yaml
│  └─ audit/
│     └─ log.screen.yaml
├─ fixtures/
└─ openapi/
```

`pages`の階層はファイル整理のための配置です。YAML内のScreen Groupやroute階層とは独立します。

## components（共通コンポーネント）

再利用する部品を種別ごとの文書に定義します。`fields.yaml`の`EmailField`は外部`$ref`で
`validations.yaml`の`Required`と`EmailFormat`を参照します。

```yaml
# components/fields.yaml
specVersion: "0.1"
components:
  fields:
    EmailField:
      label: メールアドレス
      type: email
      required: true
      validations:
        - $ref: "./validations.yaml#/components/validations/Required"
        - $ref: "./validations.yaml#/components/validations/EmailFormat"
```

## pages/users/edit.screen.yaml（画面）

`fields`はマップで、キー（`name` / `email` / `role`）が識別子・記述順が表示順です。
`email`は外部Componentを純粋参照し、`role`の動的Optionsは`getUser → data.roleOptions → role.options`として接続します。Viewerではこの供給経路とOpenAPI response pathの照合結果を確認できます。

```yaml
specVersion: "0.1"
screen:
  id: user-edit
  name: ユーザー編集画面
  description: ユーザー情報を編集する画面
  route: /users/{userId}/edit
  fields:
    name:
      label: 氏名
      type: text
      required: true
      validations:
        - $ref: "../../components/validations.yaml#/components/validations/Required"
        - rule: maxLength
          value: 50
          message: 50文字以内で入力してください
    email:
      $ref: "../../components/fields.yaml#/components/fields/EmailField"
    role:
      label: ロール
      type: select
      placeholder: ロールを選択

  data:
    roleOptions:
      schema:
        type: array
        items:
          type: object
          properties:
            id: { type: string }
            name: { type: string }

  fieldBindings:
    role:
      options:
        source: data.roleOptions
        item: { value: id, label: name }
      loading:
        source: api.getUser.loading

  apiBindings:
    getUser:
      openapi:
        operationId: getUserById
        specRef: ../../openapi/users.yaml
      response:
        mapping:
          fields.role: data.role
          data.roleOptions: roleOptions
```

## 検証してみる

```bash
npm run validate examples/pages/users/edit.screen.yaml
# ✓ examples/pages/users/edit.screen.yaml is valid
```

不正例`examples/fixtures/invalid/screen.screen.yaml`は、id命名・キー命名・`$ref`純粋性の違反を含み、
検証に失敗します（[検証フロー](/concepts/validation)）。
