# コレクションはマップ

`fields` などのコレクションは、配列＋`id` ではなく **マップ** で表現します。
マップのキーがそのまま識別子になり、`id` プロパティは持ちません。

```yaml
screen:
  id: user-edit
  name: ユーザー編集画面
  fields:
    name:                 # キー "name" がフィールド識別子
      label: 氏名
      type: text
    email:                # キー "email" がフィールド識別子
      label: メール
      type: email
```

## 記述順が表示順

マップは構造的には順序非依存ですが、screen-spec では **YAML の記述順を表示順とみなします**。
上の例では「氏名 → メール」の順で表示されることを意味します。

これは OpenAPI がマップ主体である慣習に沿いつつ、画面設計で必要な「並び」を軽量に扱うための
決定です。厳密なレイアウト（配置・グリッド）は後続バージョンで別途扱います。

## なぜマップなのか

- OpenAPI と同じく、識別子をキーで表現できる
- `$ref` した項目に本体側で `id` を併記する必要がなくなり、`$ref` の純粋性を保てる
  （[`$ref` ガイド](/concepts/refs) を参照）
