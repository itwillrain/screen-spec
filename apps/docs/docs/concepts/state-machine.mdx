# 状態遷移

画面が取りうる状態と、その間の遷移を記述します。v0.1 は **案C（中間）** の厳密さを採ります。

- `states`：状態の定義（マップ。1 つを `initial: true`）
- `events`：状態間の遷移（`from` と、`to` または順序付き `branches`）
- `transitions`：画面間の遷移（遷移先の画面 id）

## 例

```yaml
states:
  viewing: { name: 閲覧中, initial: true }
  editing: { name: 編集中 }
  submitting: { name: 送信中 }
  error: { name: エラー }

events:
  edit:
    trigger: click
    from: viewing
    to: editing
  submit:
    trigger: click
    from: editing
    to: submitting
    action: { apiCall: updateUser }
    onSuccess: { to: viewing, navigate: user-list }
    onError: { to: error }
  cancel:
    from: editing
    to: viewing
  retry:
    from: error
    to: editing

transitions:
  toUserList:
    to: user-list
    trigger: submit.onSuccess
```

## 検証と診断（案C）

`states`/`events` は JSON Schema 検証に加え、意味解析を行います。

- **error**：`from` / `to` / `onSuccess.to` / `onError.to` が**未定義の状態**を参照している
- **warning**：初期状態が 0 個または複数、**到達不能な状態**がある

設計途中を許容するため、到達性などは **警告**に留めます（エラーにはしません）。

## 条件分岐

`branches` は上から順に評価し、最初に一致した Branch の結果だけを実行します。末尾に `otherwise: true` を置けます。fallback がなければ No Match となり、状態遷移・API呼び出し・副作用は発生しません。Viewer は Branch をノードではなく条件付きエッジとして表示します。

入れ子/並行状態、履歴状態、任意スクリプトは v0.1 の非スコープです。
