# Field Review Workspace

Viewerの「項目」タブは、エンジニア向けの読み取り専用レビュー領域です。デザイン画像を左、FieldとUI Componentを統合した画面要素一覧と選択要素の詳細を右に表示します。デザインが未登録なら画面要素領域を全幅で使用します。

## 画面要素を探す

画面要素一覧はFieldとUI Component InstanceをHeader、Sidebar、Body、Footerの定義順に表示します。要素ID、名称、文言、セクション名の検索に加え、型、Event連携、条件、診断の有無で絞り込めます。Componentは開閉可能なチャンクで、展開すると内部Fieldを `instanceId.fieldId` の通常のField行としてフラットに表示します。一致する要素を単一テーブル内のセクション見出しごとにまとめ、Layout未配置の要素は最後の「未配置」グループへまとめます。

## Fieldを追跡する

行を選択すると、そのField型に適用される既定値、Validation、Optionsと、定義済みの条件式、Componentの`$ref`、Layout情報を右側の詳細に表示します。動的Optionsでは`API Binding → Screen Data → Field Input`、response path、value／label mapping、loading sourceを一続きで表示し、OpenAPIとのpath照合結果も示します。非該当の項目や、内容のない診断・関連Eventは表示しません。`eventId`またはEventの`target`で直接関連するEventを、Trigger、Event Context、BranchまたはAction、Result、Success・Errorの実行順で確認できます。

選択中の画面、タブ、Field、デザイン画像はURLで共有できます。ペイン幅、ズーム、折りたたみ状態はブラウザへ保存します。

## Componentを追跡する

Field ComponentはOrigin、Validation ComponentはValidation欄、Options ComponentはOptions欄に表示します。UI Component Instanceは画面要素一覧へ直接表示し、内部Fieldを同じチャンク内で確認できます。Component名を選ぶと右ドロワーでComponent定義とDependencyを開きますが、Dependencyをパンくず状にはネストしません。

Component操作はbuttonで提供し、詳細を開いたら見出しへフォーカスを移します。チャンクの一括開閉、URL共有、キーボード操作、狭幅での全幅ドロワーに対応します。独立したComponent Catalogは設けません。詳しくは[Component Usage](/concepts/component-usage)を参照してください。

## デザイン参照

`design.images`は切り替え、幅合わせ、原寸、拡大・縮小、ドラッグ移動、リセット、別タブ表示に対応します。Design Mappingがあれば画像上に番号付き領域を表示し、領域と画面要素行をホバー・選択で双方向に連動します。画面要素を選んだとき、対応Mappingが別画像にあればその画像へ切り替えます。

Design Tourは画像順とMapping定義順に画面要素を巡回します。前へ・次へで対象領域を中央へ移動し、画面要素の名称、ID、詳細を同時に確認できます。Figmaと外部リンクはViewer外で開きます。狭い画面ではFieldを優先し、デザイン領域を折りたためます。

ViewerからのYAML編集、画像領域の作成・移動、Figma埋め込み、仕様からのUI仮描画は行いません。Mapping編集は将来のEditorとして別に扱います。
