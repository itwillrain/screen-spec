# Field Review Workspace

Viewerの「項目」タブは、エンジニア向けの読み取り専用レビュー領域です。デザイン画像を左、Field一覧と選択Fieldの詳細を右に表示します。デザインが未登録ならField領域を全幅で使用します。

## Fieldを探す

Field ID、ラベル、文言の検索に加え、型、Event連携、表示・有効条件、診断の有無で絞り込めます。一覧はFieldの定義順を維持し、Field ID、セクション、ラベル／文言、型、必須、Event ID、error／warning件数を表示します。連続する同一セクションは先頭行だけに表示し、Layout未配置のFieldは「未配置」と示します。

## Fieldを追跡する

行を選択すると、そのField型に適用される既定値、Validation、Optionsと、定義済みの条件式、Componentの`$ref`、Layout情報を右側の詳細に表示します。動的Optionsでは`API Binding → Screen Data → Field Input`、response path、value／label mapping、loading sourceを一続きで表示し、OpenAPIとのpath照合結果も示します。非該当の項目や、内容のない診断・関連Eventは表示しません。`eventId`またはEventの`target`で直接関連するEventについて、Branch順序、条件、遷移先、API Call、成功・エラー結果を一段だけ確認できます。

選択中の画面、タブ、Field、デザイン画像はURLで共有できます。ペイン幅、ズーム、折りたたみ状態はブラウザへ保存します。

## Componentを追跡する

Field Originは`Inline`またはField Componentとして表示し、Validation UsageとOptions Usageを分けます。Component名を選ぶと同じ右ドロワー内でComponent ContractとDependencyを開き、パンくずと戻る操作でFieldへ戻れます。現在画面の利用Fieldを先に表示し、プロジェクト内の他画面にある利用箇所とImpacted Fieldへ移動できます。

Component操作はbuttonで提供し、詳細を開いたら見出しへフォーカスを移します。パンくずはnavとして表現し、URL共有、キーボード操作、狭幅での全幅ドロワーに対応します。独立したComponent Catalogは設けません。詳しくは[Component Usage](/concepts/component-usage)を参照してください。

## デザイン参照

`design.images`は切り替え、幅合わせ、原寸、拡大・縮小、ドラッグ移動、リセット、別タブ表示に対応します。Figmaと外部リンクはViewer外で開きます。狭い画面ではFieldを優先し、デザイン領域を折りたためます。

ViewerからのYAML編集、画像注釈、Fieldとの座標連動、Figma埋め込み、仕様からのUI仮描画は行いません。編集機能は将来のEditorとして別に扱います。
