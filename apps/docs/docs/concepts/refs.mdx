# `$ref` ガイド

コンポーネントの再利用は `$ref` で行います。v0.1 から**必須の機能**であり、OpenAPI の
`components` + `$ref` モデルを踏襲しています。

## 純粋参照（マージ禁止）

`$ref` を持つオブジェクトには **兄弟キーを書けません**。マージや上書きはできません（OpenAPI 3.0 互換）。

```yaml
# OK: 純粋参照
email:
  $ref: "./common.yaml#/components/fields/EmailField"
```

```yaml
# NG: 兄弟キー併記 → 検証エラー
email:
  $ref: "./common.yaml#/components/fields/EmailField"
  label: 上書きのつもり
```

## バリエーションは別コンポーネント

「共通定義とほぼ同じだが少し違う版」が欲しい場合は、**上書きではなく別コンポーネントとして定義**します。

```yaml
components:
  fields:
    EmailField:
      label: メールアドレス
      type: email
      required: true
    OptionalEmailField:      # 別コンポーネントとして定義
      label: メールアドレス（任意）
      type: email
      required: false
```

## 参照の形式

- **内部参照**: `#/components/validations/Required`
- **外部参照**: `./common.yaml#/components/fields/EmailField`

v0.1 では **ローカル相対パスのみ**をサポートします。`http(s)://` などのリモート参照や
絶対パスは許可されません。循環参照は検出されエラーになります。

## 合成（compose）

`$ref` はマージしませんが、「共通定義＋少し違う版」を上書きで表現したい場合のために
**`compose`**（`allOf` 相当の**明示的な合成宣言**）があります。`$ref` 単体の純粋性は保ったままです。

```yaml
altEmail:
  compose:
    - $ref: "./common.yaml#/components/fields/EmailField"
  label: 予備メールアドレス   # 兄弟キーはローカルな上書き（最優先）
  required: false
```

- `compose` の各要素を順にマージ（後勝ち）し、さらに兄弟キー（`compose` 以外）を最優先でマージ。
- マージ結果は本来の型（Field など）として再検証されます。
- 使える位置: Field / Validation（v0.1）。
